CourseWave Backend — Current Context
====================================

Objective
---------
Consolidate the CourseWave backend into a single FastAPI service and finish the
requested refinements:
- JSON-only response caching.
- Configurable prefix-based rate limiting with a strategy-to-handler registry.
- Student auth methods (EMAIL | GOOGLE) with nullable password hashes.
- Removal of the transactional outbox model.
- The backend is the public API; api_gateway/ has been deleted.
- RabbitMQ replaces Kafka.
- No Docker containers are started during development/validation.


Confirmed Requirements and Decisions
------------------------------------
Caching
- Cache only responses whose media type is exactly application/json.
- Media-type parameters are allowed, e.g. application/json; charset=utf-8.
- Do not cache application/problem+json or any other non-JSON media type.
- Only paths under CACHE_ROUTES are cache candidates. The tuple lives in
  backend/app/middleware/cache.py and contains /student/api/v1 and
  /instructor/api/v1. Matching is segment-aware, so /student/api/v10 does not
  match /student/api/v1.
- Paths outside CACHE_ROUTES bypass cache reads and writes and do not get an
  X-Cache header.
- Non-JSON GET responses under a cache route stream through without buffering
  and still get X-Cache: MISS.
- Public, cookie-free, non-authenticated 200 GET responses only.
- Cache key: cache:<path> plus ?<raw query string> when present.
- TTL: CACHE_TTL_SECONDS (420 seconds by default).
- Do not cache Set-Cookie, Cache-Control: no-store/private, Vary: *, streaming
  responses, or bodies over 1 MiB.
- Redis failures fail open.

Rate limiting
- Setting is ratelimit_routes: a native list[dict[str, Any]] whose entries are
  exactly {prefix, window_ms, strategy}.
- Defaults:
    {"prefix": "/student/api", "window_ms": 90000, "strategy": "fixed_window"}
    {"prefix": "*", "window_ms": 90000, "strategy": "fixed_window"}
- Unmatched paths use the fallback
  {"prefix": "*", "window_ms": 90000, "strategy": "fixed_window"}.
- Match request paths against configured prefixes in list order; the first
  matching prefix wins. `*` matches any path, and unmatched paths use the
  built-in `{"window_ms": 90000, "strategy": "fixed_window"}` fallback.
- Resolve strategy through backend/app/middleware/ratelimit/ratelimiter_registry.py.
- RATELIMITER_REGISTRY maps both fixed_window and token_bucket to async handlers.
- Handlers take the request and window_ms and return bool.
- The middleware pre-binds Redis and RATE_LIMIT_MAX with functools.partial.
- Handlers publish RateLimitResult via scope["state"]["ratelimit_result"].
- The middleware sets X-RateLimit-Limit, X-RateLimit-Remaining,
  X-RateLimit-Reset, and Retry-After (429 only) from that metadata.
- RATE_LIMIT_MAX remains the fixed-window request cap for both strategies.
- Route entries stay exactly three keys.
- Use ratelimit_ only for the new route setting; all other RATE_LIMIT_* names
  remain unchanged.
- RATE_LIMIT_WINDOW_MS was removed because each route carries window_ms.
- Unknown strategies log a warning and fall back to fixed_window.
- Redis failures fail open.

Prior decisions that remain in place
- Student registration remains public and unchanged.
- Student.auth_method is an AuthMethod enum with EMAIL = "email" and
  GOOGLE = "google"; the database enum is named auth_method and stores the
  lowercase values.
- Student.password_hash is nullable with a NULL default, but email
  registration still hashes and stores a password.
- register_student sets auth_method=AuthMethod.EMAIL explicitly.
- The Outbox model and all outbox writes are removed. RabbitMQ remains
  provisioned in Compose but is currently unused.
- New error bodies use {"detail": "..."}.
- Compose service is named coursewave, builds ./backend, publishes 3000:8000.
- RabbitMQ replaces Kafka; Kafka and api_gateway/ are removed.
- Refresh is BaseHTTPMiddleware handling POST /auth/api/v1/token-refresh.
- Auth, Cache, RateLimit, RefreshToken, and RequestLogger are all Starlette
  BaseHTTPMiddleware; CORS remains the built-in CORSMiddleware.
- Cache only public GETs under CACHE_ROUTES (no Authorization, no Cookie, no
  authenticated session).
- Anonymous rate limiting keys on the socket IP.
- Middleware order is
  CORS -> RequestLogger -> Auth -> RateLimit -> RefreshToken -> Cache -> routes.
- Do not start Docker Desktop or any containers.

Important Context
-----------------
- Authentication: HS256 Bearer access JWT signed with JWT_SECRET, type must be
  "access", sessionId must be present, and Redis key session:<sessionId> must
  hold {userId, role, email}. The parsed session is stored as
  request.state.user (scope["state"]["user"]).
- Refresh: signed cookie refresh=s:<JWT>.<HMAC-SHA256 base64 without padding>
  using COOKIE_SECRET. The refresh JWT uses JWT_SECRET, type must be "refresh",
  and the session TTL is extended to 604800 seconds. New access and refresh
  tokens reuse the same session ID. Cookie attributes: HttpOnly, Secure,
  SameSite=Strict, Path=/auth/api/v1/token-refresh, Max-Age=604800.
- Cache routes: CACHE_ROUTES = ("/student/api/v1", "/instructor/api/v1") in
  cache.py. Matching is segment-aware; non-matching paths skip Redis and have
  no X-Cache header. Cache key is cache:<path>[?<query>].
- RequestLogger measures duration until the response object is produced, so
  streamed body transfer time is not included.
- Rate-limit keys: ratelimit:<strategy>:<prefix>:<identifier>.
- Identifiers: authenticated session userId, otherwise socket IP.
- Default RATE_LIMIT_MAX is 100.
- Token-bucket capacity is RATE_LIMIT_MAX and refills RATE_LIMIT_MAX tokens
  over the route window_ms.
- RATELIMIT_ROUTES is supplied as JSON in the environment and parsed by
  pydantic-settings into a list of dicts.
- Compose service publishes host port 3000 to container port 8000.
- Registration remains public at /student/api/v1/register.
- Student auth: AuthMethod.EMAIL.value == "email" and
  AuthMethod.GOOGLE.value == "google". The auth_method column is non-nullable
  and defaults to AuthMethod.EMAIL.
- password_hash is str | None with a NULL default; registration still stores an
  Argon2 hash for email accounts, and future Google accounts can leave it null.
- Registration stores the verification token in Redis with a 120-second TTL but
  no longer enqueues an outbox event or builds an email verification link.
- All new error responses use {"detail": "..."}.
- The repository root C:\Users\USER\coursewave is the git repository; the
  remote is https://github.com/geraldrolland/coursewave.git (main).
- api_gateway/ was its own repository and has been removed permanently.
