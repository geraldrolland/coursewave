2. Middleware
Order

Effective request flow:

This ensures:

- 401/429/refresh responses are logged.
- Rate limiting sees the authenticated user.
- Refresh is rate-limited but skips auth.

Auth — backend/app/middleware/auth.py
Port api_gateway/src/middleware/auth.ts:
1. Skip configured excluded paths.
2. Require Authorization: Bearer <token>.
3. Verify HS256 JWT with JWT_SECRET.
4. Require type == "access".
5. Require non-empty sessionId.
6. Load Redis key session:<sessionId>.
7. Store the parsed session in scope["state"]["user"].
Responses:
Condition	Status	Detail
Missing/malformed header	401	Missing or invalid Authorization header
Invalid/expired JWT	401	Invalid or expired token
Wrong token type	401	Invalid token type
Missing session ID	401	Invalid token payload
Session missing	401	Session expired or not found
Redis/unexpected failure	500	Authentication service unavailable

Cache — backend/app/middleware/cache.py
- Only GET.
- Skip when any of these are true:
- path is excluded (/health by default)
- Authorization header exists
- Cookie header exists
- scope["state"]["user"] is populated
- Key: cache:<path> plus ?<raw query string> when present.
- TTL: 420 seconds.
- Add X-Cache: HIT / MISS.
- Cache only 200 responses without:
- Set-Cookie
- Cache-Control: no-store or private
- Vary: *
- Buffer only responses up to 1 MiB; do not cache streaming responses.
- Store status, headers, and base64-encoded body as JSON.
- Fail open on any Redis error.
- Do not cache authenticated or cookie-bearing responses, preventing cross-user leakage.
Rate limiting — backend/app/middleware/ratelimit/
Mirror the gateway package:
ratelimit/__init__.py       route matching, identifier, headers, middleware
ratelimit/fixed_window.py   Redis INCR/EXPIRE implementation
ratelimit/token_bucket.py   Redis Lua token bucket
ratelimit/utils.py          identifier/header helpers
Behavior:
- Identifier: session userId when authenticated, otherwise socket IP (scope["client"][0]).
- Longest-prefix route matching; global fallback uses fixed window.
- Fixed-window keys: ratelimit:fixed:<route>:<identifier>.
- Token-bucket keys: ratelimit:bucket:<route>:<identifier>.
- Headers:
X-RateLimit-Limit
X-RateLimit-Remaining
X-RateLimit-Reset
Retry-After        # 429 only
- 429 body:
{"detail": "Too many requests, please try again later"}
- Skip /health.
- Fail open on Redis errors, matching gateway behavior.
Refresh — backend/app/middleware/refresh_token.py
This is an ASGI middleware, not a FastAPI route.
Condition:
scope["type"] == "http"
scope["method"] == "POST"
scope["path"].rstrip("/") == "/auth/api/v1/token-refresh"
Flow:
1. Read the refresh cookie.
2. Require the s: signed-cookie prefix and verify HMAC with COOKIE_SECRET.
3. Verify the refresh JWT with JWT_SECRET.
4. Require type == "refresh" and sessionId.
5. Require session:<sessionId> in Redis.
6. Extend the session TTL to 604800 seconds.
7. Issue a new access token and refresh token for the same session ID.
8. Set a new signed refresh cookie:
HttpOnly; Secure; SameSite=Strict;
Path=/auth/api/v1/token-refresh; Max-Age=604800
 9. Return 200 {"accessToken": "<new-access-token>"}.
10. If the path does not match, call the next middleware.
Errors:
Condition	Status	Detail
Missing/unsigned cookie	401	Missing refresh token
Wrong token type	401	Invalid token type
Missing session ID	401	Invalid refresh token payload
Session missing	401	Session expired or not found
Invalid/expired JWT	401	Invalid or expired refresh token
Unexpected failure	500	Token refresh failed
I’ll use /auth/api/v1/token-refresh because that is the gateway endpoint. If you actually want /auth/api/refresh-token, tell me before implementation.
